## 1. Моя роль одной фразой

> «Я — **семантический поиск** системы. Я превращаю текст в числовые векторы (эмбеддинги), храню их в векторной базе FAISS и по любому вопросу мгновенно нахожу самые подходящие по смыслу фрагменты. Это «мост» между сырыми чанками и нейросетью, которая пишет ответ.»

## 2. Что именно сделано

1. **Эмбеддинги** — каждый чанк кодируется моделью `all-MiniLM-L6-v2` в вектор из 384 чисел.
2. **Векторная база FAISS** — индекс `IndexFlatIP` для точного косинусного поиска; индекс и метаданные кэшируются на диск.
3. **Retrieval** — по вопросу строится его вектор, возвращаются top-k ближайших чанков со скорами похожести, с фильтром по минимальному скору.

## 3. Какие технологии и почему

| Технология | Зачем |
|---|---|
| **sentence-transformers / all-MiniLM-L6-v2** | Рекомендованная моделью задания. Маленькая (~80 МБ), быстрая на CPU, даёт сильные семантические эмбеддинги. 384 измерения — хороший баланс «качество/скорость». |
| **FAISS (faiss-cpu)** | Быстрая, локальная (без API и интернета) библиотека поиска по векторам от Meta. Идеальна для нашего объёма. |
| **`IndexFlatIP` + L2-нормализация** | На нормированных векторах внутреннее произведение = косинусное сходство. «Flat» = точный перебор → 100% recall без потерь, что при 28 векторах быстрее и проще, чем приближённые индексы (IVF/HNSW). |

## 4. Как это работает (для слайда «механика»)

**Что такое эмбеддинг (объяснение «на пальцах»):** модель переводит текст в точку в 384-мерном пространстве так, что близкие по смыслу тексты оказываются рядом. «Армия», «легион», «солдаты» — рядом; «торговля», «монеты» — в другой области. Поиск по смыслу = поиск ближайших точек.

**Шаг A. Кодирование чанков (нормализуем сразу):**
```python
vecs = model.encode(texts, convert_to_numpy=True,
                    normalize_embeddings=True).astype("float32")  # (28, 384)
```

**Шаг B. Построение индекса:**
```python
index = faiss.IndexFlatIP(384)   # inner product == cosine на единичных векторах
index.add(embeddings)
```

**Шаг C. Поиск по вопросу:**
```python
qvec = self._embed([query])             # тот же энкодер, что и для чанков!
scores, idxs = self.index.search(qvec, k)   # top-k ближайших
```
> **Ключевой принцип:** вопрос и чанки кодируются **одной и той же** моделью — иначе они окажутся в разных «пространствах» и поиск сломается.

**Пример (реальный):** вопрос *«How was the Roman army organised?»* → топ-1 чанк `[4. The Roman Military]` со скором **0.616**.

## 5. Почему это важно (ценность для проекта)

- **Семантика, а не ключевые слова.** Обычный поиск (Ctrl+F) ищет точные слова. Мы ищем по **смыслу**: вопрос «во что верили римляне?» найдёт раздел про религию, даже если слова «верили» в тексте нет.
- **Скорость.** После однократного построения индекс кэшируется; поиск занимает **миллисекунды**.
- **Это «R» в RAG.** Именно retrieval даёт нейросети факты из нашего документа вместо «галлюцинаций» из её памяти.
- **Локальность и приватность.** Всё считается на машине, без отправки данных во внешний поисковый сервис.

## 6. Результат (цифры для слайда)

- **28 векторов × 384 измерения**, индекс FAISS `IndexFlatIP`.
- Построение индекса (включая эмбеддинги): **< 1 c** после загрузки модели.
- Поиск по запросу: **~5–15 мс**.
- **Retrieval accuracy: 10/10 (100%)** — на 10 контрольных вопросах нужный раздел всегда в top-4.
- Средний скор топ-1: **0.615** (диапазон ~0.55–0.73).

## 7. Технические решения, которыми можно «блеснуть»

- **Нормализация → косинус через dot product:** не считаем косинус явно, а нормируем векторы и берём внутреннее произведение — быстрее и проще.
- **Кэширование индекса:** медленный шаг (эмбеддинги) выполняется один раз, дальше — мгновенная загрузка из `data/faiss.index` + `data/chunks.json`.
- **Обход бага Windows:** `faiss.write_index()` не открывает пути с кириллицей (папка «Документы»). Решение — сериализовать индекс в байты и писать средствами Python:
  ```python
  open(INDEX_PATH, "wb").write(faiss.serialize_index(index).tobytes())
  ```

## 9. Вероятные вопросы (и ответы)

- **Почему FAISS, а не Pinecone/Chroma?** — Локально, без ключей и сети, мгновенно; для нашего объёма точный flat-индекс идеален. Pinecone — облачный, нужен для миллионов векторов.
- **Что такое 384 измерения?** — Длина вектора-эмбеддинга у MiniLM; компромисс между выразительностью и скоростью.
- **Что значит скор 0.6?** — Косинусное сходство от −1 до 1; чем ближе к 1, тем более семантически похоже. 0.6–0.7 для топ-результатов — хороший показатель.
- **Почему k=4?** — В рекомендованном диапазоне 3–5: достаточно фактов нейросети, но без «замусоривания» промпта лишним.
