## 1. Моя роль одной фразой

> «Я — **«генератор ответа» и «лицо» системы**. Беру найденные фрагменты, грамотно вставляю их в промпт, прошу нейросеть (Gemini или Claude) написать связный ответ **строго по этим фактам и с цитатами**, и показываю всё пользователю через CLI и веб-приложение. А ещё измеряю, насколько хорошо всё работает.»

## 2. Что именно сделано

1. **Промпт-инжиниринг** — шаблон, который вставляет найденный контекст и заставляет модель отвечать только по нему и ссылаться на разделы.
2. **Интеграция LLM** — автоопределение провайдера: **Gemini** (по умолчанию) или **Claude**; если ключа нет — extractive-режим (показ найденных фрагментов).
3. **Интерфейсы** — CLI (`query_cli.py`) и удобное **веб-приложение на Streamlit** (`app.py`).
4. **Оценка** — `evaluate.py`: прогон 10 вопросов, метрики точности и скорости, отчёт `docs/results.md`.

## 3. Какие технологии и почему

| Технология | Зачем |
|---|---|
| **Google Gemini** (`google-genai`, модель `gemini-2.5-flash`) | Быстрая и доступная LLM; основной провайдер по выбору команды. |
| **Anthropic Claude** (`anthropic`) | Запасной/альтернативный провайдер — показывает, что архитектура не привязана к одному вендору. |
| **Промпт с инъекцией контекста** | Сердце RAG: модель отвечает по нашим фактам, а не «из головы» → нет галлюцинаций, есть цитаты. |
| **Streamlit** | Минимум кода → красивый веб-интерфейс: поле вопроса, ответ, источники, сравнение режимов. |
| **Свой eval-харнесс** | Превращает «вроде работает» в измеримые числа (accuracy, latency). |

## 4. Как это работает (для слайда «механика»)

**Шаг A. Сборка промпта** — каждый найденный фрагмент помечается источником:
```python
context = "\n\n---\n\n".join(f"[Source: {r.chunk.section}]\n{r.chunk.text}"
                            for r in contexts)
prompt = ("Answer using ONLY the context passages below. Cite the section "
          "titles in square brackets, e.g. [4. The Roman Military]. If the "
          f"answer is not in the context, say so.\n\nCONTEXT\n{context}\n\nQUESTION\n{query}")
```
Три приёма промпт-инжиниринга: (1) «отвечай **только** по контексту», (2) «**цитируй** разделы», (3) «если ответа нет — **так и скажи**» (защита от выдумывания).

**Шаг B. Вызов LLM с автовыбором провайдера:**
```python
def llm_provider():
    if os.environ.get("GEMINI_API_KEY"):    return "gemini"
    if os.environ.get("ANTHROPIC_API_KEY"): return "anthropic"
    return None   # → extractive-режим
```

**Шаг C. Тонкость с Gemini (можно показать как «глубину»):** у `gemini-2.5-flash` по умолчанию включён скрытый режим *thinking*, и эти токены съедают лимит ответа — длинные ответы обрезались. Отключили thinking, чтобы весь бюджет шёл в видимый текст:
```python
config=types.GenerateContentConfig(
    max_output_tokens=2048,
    thinking_config=types.ThinkingConfig(thinking_budget=0),  # ← фикс обрезания
)
```

**Шаг D. Интерфейсы.** CLI для разработчика; Streamlit-приложение для пользователя (вставка ключа прямо в браузере, кнопки-примеры, ответ + раскрывающиеся источники, режим «с RAG / без RAG»).

## 5. Почему это важно (ценность для проекта)

- **RAG убирает галлюцинации.** Без контекста модель «фантазирует общими словами»; с контекстом отвечает **конкретно и по делу**.
- **Проверяемость.** Каждый ответ ссылается на раздел-источник — пользователь может перепроверить.
- **Гибкость.** Один интерфейс `_call_llm()` — два провайдера + безопасный fallback. Нет ключа — система всё равно работает (показывает релевантные пассажи).
- **Доступность.** Веб-приложение делает технологию понятной любому: не нужно знать код, чтобы задать вопрос.

## 6. Демонстрация «до/после RAG» (ключевой момент презентации)

В приложении есть галочка **«Compare: with vs. without RAG»**:

| | Без RAG (память модели) | С RAG (наш документ) |
|---|---|---|
| Опора | общие знания, расплывчато | факты из PDF |
| Цитаты | нет | `[9. Crisis, Reform, and Division]` |
| Неизвестный вопрос | может выдумать | «этого нет в документе» |
| Длина/конкретика | длинно и обобщённо | коротко и точно |

Реальный пример (вопрос про Кризис III века): ответ **без RAG** — ~3700 символов общих рассуждений; ответ **с RAG** — ~470 символов точного факта с цитатой.

## 9. Вероятные вопросы (и ответы)

- **Что такое RAG в двух словах?** — Retrieval-Augmented Generation: сначала **находим** релевантные факты (Части 1–2), потом **даём их нейросети** написать ответ. Память модели + наш проверенный источник.
- **Почему не просто спросить ChatGPT/Gemini?** — Без контекста модель может выдумать и не сошлётся на источник; RAG привязывает ответ к нашему документу и даёт цитаты.
- **Чем хорош промпт-инжиниринг здесь?** — Тремя инструкциями (только контекст / цитируй / признавай незнание) превращаем модель из «болтуна» в «аккуратного ассистента».
- **А если нет API-ключа?** — Система не падает: работает extractive-режим, возвращая самые релевантные пассажи.
